# git-commit

변경 사항을 전부 스테이징하고, 커밋 메시지를 자동 생성한 뒤, 팝업으로 사용자에게 확인·수정받고 커밋한다.

## 절차

1. **현재 상태 확인**
   - `git status --short`와 `git diff HEAD`를 실행해 무엇이 변경됐는지 파악한다.
   - 변경 사항이 전혀 없으면 커밋할 게 없다고 알리고 종료한다.

2. **전부 스테이징**
   ```bash
   git add -A
   ```

3. **커밋 메시지 자동 생성**
   - 스테이징된 변경(`git diff --cached`)을 근거로 커밋 메시지를 만든다.
   - 최근 커밋(`git log --oneline -10`)의 스타일을 따른다. 이 저장소는 Conventional Commits(`feat:`, `fix:` 등) + 한국어 요약을 쓴다.
   - 제목은 72자 이내 한 줄. 필요하면 본문에 변경 이유·범위를 덧붙인다.

4. **커밋 메시지 미리 보여주기** — 팝업(`AskUserQuestion`) 질문은 줄바꿈을 렌더링하지 못한다. 그러므로 팝업을 띄우기 **전에** 생성한 커밋 메시지 전문을 채팅 본문에 코드블록으로 먼저 출력해, 제목·본문이 줄바꿈된 상태로 보이게 한다.

5. **팝업으로 확인 요청** — `AskUserQuestion` 도구를 사용한다.
   - 질문(`question`)에는 "위 메시지로 커밋할까요?"처럼 짧게만 쓴다(메시지 전문은 4단계에서 이미 보여줬다).
   - `AskUserQuestion`은 명시 선택지가 최소 2개 필요하다. "수정" 선택지는 두지 말고 **"이대로 커밋" / "취소"** 두 개만 둔다. 메시지 수정은 자동 제공되는 "기타(Other)" 칸에 직접 입력한다.
   - 사용자가 "기타"로 새 메시지를 주면 그 메시지를 확정본으로 삼고, 4단계처럼 다시 보여준 뒤 5단계로 확인한다.
   - "취소"를 고르면 **묻지 말고 바로 `git reset`을 실행**해 스테이징을 되돌리고, 커밋하지 않은 채 종료한다.

6. **커밋**
   - 확정된 메시지로 커밋한다. 여러 줄이면 `-m` 을 여러 번 쓴다.
   ```bash
   git commit -m "<제목>" -m "<본문(선택)>"
   ```
   - 커밋 후 `git log --oneline -1`로 결과를 확인해 사용자에게 알린다.

## 주의

- 사용자가 팝업(5단계)에서 "이대로 커밋"을 고르기 전에는 절대 커밋하지 않는다.
- `git push`는 이 스킬 범위가 아니다. 사용자가 따로 요청하지 않는 한 푸시하지 않는다.
- 현재 브랜치가 기본 브랜치(main 등)여도, 이 스킬은 사용자가 명시적으로 커밋을 요청한 것이므로 그대로 커밋한다.
